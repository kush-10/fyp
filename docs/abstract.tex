\chapter*{Abstract}

This dissertation studies the practical cost of symmetric cryptography inside a
zero-knowledge virtual machine using RISC Zero. The work starts with
operation-level benchmarking and baseline cipher benchmarking for AES-128,
Salsa20, and LowMC, all measured through a common host/guest harness that emits
structured JSON artifacts for later aggregation.

The measurement workflow is designed for repeatability: benchmark targets are
config-driven, trials are logged per run, and aggregation emits machine-readable
summaries suitable for chapter-level evidence inserts. The harness supports
multi-trial distribution summaries, but the final report campaign is mainly
single-trial and is interpreted cautiously where small timing deltas are
involved.

The initial hypothesis was that LowMC should be favorable because of reduced
nonlinearity. In this implementation setting, measured behavior did not match
that expectation. The project therefore includes optimization work on LowMC
(bitsliced SWAR substitution, matrix hot-path changes, and precompute-oriented
host/guest inputs) and an AES optimization workspace for S-box backend
experimentation.

The final implemented system path is authenticated AES in the zkVM:
AES-CTR encryption combined with Encrypt-then-MAC using HMAC-SHA256-192. The
construction authenticates framed data
\texttt{aad || iv || ciphertext}, and the verification path checks the tag
before decryption.

In the final repository structure, CTR-only and CTR+HMAC are represented as
separate benchmark families (\texttt{aes-ctr} and \texttt{aes-ctr-hmac}) so
authenticated overhead can be measured explicitly and reproducibly.

Security analysis is presented as a game-based proof sketch rather than a full
formal reduction. The main game is an IND-CPA challenge where the adversary also
receives the HMAC tag and RISC Zero receipt; the sketch relies on nonce-respecting
AES-CTR, a PRF-style treatment of truncated HMAC tags, and proof zero-knowledge
for non-journaled witness data.

The evaluation provides directional, artifact-backed results. In the main run,
optimised LowMC remains about \(34.85\times\) slower than AES on proving time,
while LowMC optimisation reduces proving time by about \(25.59\%\) relative to
its baseline snapshot. For the final authenticated AES pipeline, adding HMAC
increases user-cycle work at every tested block size, but single-trial total-time
deltas are noisy. These results are therefore reported with explicit statistical
and reproducibility caveats rather than as cross-zkVM-general claims.
